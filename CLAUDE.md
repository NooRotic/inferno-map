# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

INFERNVS: a static, no-framework 3D cutaway of Dante's *Inferno* (Three.js r128). Every soul, guardian, place and event is a data point cited by canto and line. It is presented as a **data visualization of the text** (not a "map of Hell"), because it is shown on the owner's professional profile; keep copy and framing in that register.

## Commands

No linter or dependencies; Node runs the build script and the tests.

```bash
npm run dev            # build dist/ and serve at http://localhost:5173
npm run build          # dist/ with Three.js loaded from cdnjs
npm run build:vendor   # dist/ with Three.js copied to dist/vendor/ (use this for deploys)
python tools/make-favicon.py   # regenerate the favicon files in src/ from Lucifer's red pixel face (needs Pillow)
node --test tools/*.test.mjs   # unit tests for merge-modern and the build flags (use the glob; a bare directory fails on Node 24)
node tools/longfellow.mjs fetch    # once: save Longfellow (Gutenberg #1001) to .cache/ so the quote tests run instead of skipping
node tools/longfellow.mjs check    # every English quote in inferno.json is Longfellow's and every en line sits in its cite
node tools/longfellow.mjs XXVIII 139-142   # print lines by number (line numbers match the Italian: all 34 canto lengths agree)
node tools/build.mjs --data <dir> [--site <url>] [--title <text>] [--desc <text>]   # merge a modern data folder; no flags = the book edition, byte-identical
```

The page `fetch()`es its JSON, so `file://` does not work; always serve over HTTP. `dist/` is gitignored and wiped on every build.

## Architecture

- **`src/index.html` is a fragment** ("artifact form": no `<html>`/`<head>`). `tools/build.mjs` wraps it in a doctype/head, hoists its `<title>`, optionally rewrites the cdnjs script URL (the string match is exact, so keep that `<script src>` unchanged), and copies the two JSON files beside it. Edit `src/`, never `dist/`.
- **It is one ~1,150-line file with two `<script>` blocks**: a sprite engine (`buildPix`, turns `sprites.json` into a single canvas texture atlas) and a map engine (one IIFE: `buildEarth`, `buildLevels`, `buildLandmarks`, `buildPath`, `buildMarkers`, plus state in `setCanto`/`selectNode`/`selectLevel`). Markers are one `THREE.Points` draw call whose shader samples the sprite atlas.
- **Data drives everything** (`src/inferno.json`: `meta`, `levels`, `path`, `nodes`, `edges`; `src/sprites.json`: `palette`, `base`, `mods`, `templates`, `sprites`, `kindDefaults`). Nodes reference levels by `lv` and sprites by `icon`; edges can end on a node id or a level id. A book node may carry `torment` (the punishment as the poem states it) and `contrapasso` (why it fits the sin) with `cpconf`: the hover strip shows them in place of the trimmed `note`, and the card shows both in full under Poena and Contrapasso. Every soul must have them (`tools/torment.test.mjs`); guardians, places and events get them only where the poem shows a punishment (the giants, Lucifer, the storm, the pitch).
- **Tableaux** (`inferno.json` `tableaux`) are animated scenes tied to a level: `{ id, lv, sprite, how, node, count, lane, speed, size, hover, cite, conf, note }`, where `how` is `march` (with `backwards`), `bob`, `fall`, `flicker`, `flow` (floor scroll, no sprite), `push` (two groups with a `weight`, optional `clash` sparks), `cascade` (a falling ribbon with mist) or `track` (follows `keys` as the journey moves). `hover` lifts the figures off the floor (souls on the wind). The header comment above `buildTableaux` in `src/index.html` documents each. `node` names an existing node: hovering or tapping a figure in the scene selects it, so its card explains the sin and punishment (a scene with no `node` opens its level's card instead). `conf` follows the same rule as nodes; movement is staging, so say so in `note`. The footer Motion button turns them (and the particles) on and off and remembers the choice; it starts off when the OS asks for reduced motion. Add `?motion` to the URL to force it on.
- **Modern layer (optional)**: `tools/merge-modern.mjs` merges an external data folder (nodes with `k: event | pattern`, sources, sprites, coverage, and an optional `legend` list of `{ icon, label }` shown as an icon key in the Clavis) over the book data at build time. Modern nodes render with their own kinds and a Now toggle, and are absent when no data is merged. This repo holds no modern content; the fixtures under `tools/fixtures/` are fake and labelled TEST.
- **Journey captions**: while the journey plays, the pilgrim slows into each guardian, place and event (or, when the modern layer is merged, only each modern point, to keep the run short), holds while a credit-style caption fades in (`#jcap`), then eases on. The logic is a pure block between `/* journey:begin */` and `/* journey:end */` in `src/index.html` (tested by `tools/journey.test.mjs`, which extracts that block); keep it free of DOM and Three.js. The caption shows the node's `n`, a subtitle from its optional `cap` (else `note`, trimmed to a sentence), and the circle's optional `pun` line from `inferno.json` `levels`. A node's stop is where the pilgrim passes closest to it after it unlocks. The footer Captions button turns it off and remembers the choice. Souls get no stop.
- **Motion Fly (touch phones)**: the footer Fly button (hidden on desktop widths unless `body.motion`, set when the device is `pointer: coarse` and has `DeviceOrientationEvent`) turns the existing Fly camera into a window: the phone's back points where the camera looks; tipping it past the angle you held when Fly started (dead zone, then a ramp) flies along the view, top toward you forward and away back; twisting it like a steering wheel (right edge down) turns the Earth by orbiting the camera about the funnel's vertical axis. The maths is a pure block between `/* tilt:begin */` and `/* tilt:end */` (tested by `tools/tilt.test.mjs`; keep it free of DOM and Three.js); the sensor plumbing (`MOT`, `onTilt`, `motionStart`) sits just after it. The view moves by the change between sensor readings, so a finger drag still adds to it and switching on starts from where you already look. iOS needs `requestPermission()` inside the tap, and every browser needs HTTPS (a LAN `http://` test page gets no sensor events). The neutral angle is the pitch at the first sensor reading (`MOT.neutral`); compass heading is ignored when aimed steeper than `YAW_LOCK` because it is unstable there. While motion Fly is on, `body.tilting` shows the `#tiltHint` line above the footer buttons. Tuning knobs are in `TILT` (twist dead zone and full twist, tip dead zone, full tip forward `MOVE_MAX` and back `MOVE_MAX_BACK`, speed, spin rate, look gain, `LOOK_HOLD`). Back reaches full speed at a smaller tip than forward because a wrist bends back less far. Past `LOOK_HOLD` of tip the view stops following the phone (`tiltLookPitch` clamps the pitch the view follows, and heading is ignored), so tipping hard to fly holds the picture still; the debug line then shows `hold`. The tip ranges were set from the owner's `?tiltdebug` screen recording (2026-11-14): about 16 degrees toward you and 12 away is all a hand can hold while still seeing the screen. Tipping toward you (`tiltMove` is `-sign(d)`) flies forward; this direction was flipped after the owner's phone test, so do not flip it back. Twist is multiplied by `tiltRollGate(pitch)`, which fades it to zero between `ROLL_FADE_START` and `ROLL_FADE_END` because roll is ill-defined when aimed near straight up or down. Pinching while flying moves you forward and back, and dragging two fingers strafes (sideways, up and down); both scale with the camera's distance from the funnel (minimum step 0.4). Add `?tiltdebug` to the URL and tap Fly to replace the hint line with live pitch, start, tip, move, roll, gate and speed numbers (the match tolerates an encoded character before it). The look and twist values are owner-confirmed on a phone (2026-11-14); the tip ramp and view hold were retuned the same day from the owner's recording and await a phone test. Do not retune without feedback.
- **Modern echoes and flags (merged data only)**: a modern node's `echoes` names the book point it echoes; its optional `also` lists more book points or levels, as ids or `{ to, note }` (the note is the link's label). Book cards list the modern entries placed in the same circle under "In this circle, today"; modern cards list every echo. An optional `flag` (two capital letters) draws a small flag chip beside the place on the card and the journey caption; the shapes come from the data's top-level `flags` object (`{ US: { shapes: [{ t: 'r' | 'p' | 'c' | 'l', ... f: '#rrggbb' }] } }` on a 24 x 16 canvas), so the engine holds no flag content. A held journey caption (pause, or tap the caption) stays until you click the map, press Esc or press Play; the itinerary card fades while a caption shows.
- **Bad data is skipped, not fatal**: nodes with an unknown level, edges with a missing end, and unknown sprite mods log a `console.warn` and are dropped. When editing data, check the browser console, since a typo silently removes a point.
- **Coordinates are polar** around the funnel axis (`lv`, `a`, `r`, `h`; `y`/`rad` override). Keep `a` out of the cut wedge, 140-200 degrees. The first Roman numeral of a node's `cite` is the canto that unlocks it on the journey, so changing a citation changes when the point appears.
- All paths are relative, so the site works at a domain root or in a subfolder. Everything is same-origin static files plus cdnjs and Google Fonts.

## Content rules (these matter more than code style)

- Citations are canto + line. `docs/RESEARCH.md` is the verification log. Every English quote is checked against Longfellow by `node tools/longfellow.mjs check` (and by the tests once the text is fetched); the Italian is still partly unverified. Do not "fix" a quote or line number from memory; verify it against Longfellow (Project Gutenberg #1001) or leave it flagged. Anything in curly quotes in a note, caption, torment or contrapasso counts as a quote, so a gloss or paraphrase goes without quotation marks.
- English quotes are Longfellow 1867 only (public domain). Do not add quotes from modern translations (Ciardi, Mandelbaum, Pinsky, etc.).
- Keep the `conf` field honest: `text` for what Dante states, `interp` for interpretation. Contrapasso is mostly interpretation: `cpconf` is `text` only where the poem itself says why the punishment fits (Bertran de Born, Capaneus, Amphiaraus, Nicholas III's pun, the sowers of discord, Ephialtes, Nimrod, the sullen, the suicides, the barrators, Cacus, the hoarding clergy), otherwise `interp`. Describe torments plainly, as the poem states them.
